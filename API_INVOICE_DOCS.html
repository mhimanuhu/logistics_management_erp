How Invoice Numbering Works

🔢 Backend Auto-Generation — invoice_prefix & invoice_number

Both fields are generated entirely on the server. The frontend must never send these fields.

invoice_prefix is derived from the Indian Financial Year (April → March). The server queries MAX(invoice_number) for that prefix and increments by 1, zero-padded to 3 digits.

KLS/26-27/001
Apr 2026 – Mar 2027 · 1st invoice
KLS/26-27/042
Apr 2026 – Mar 2027 · 42nd invoice
KLS/27-28/001
Apr 2027 – Mar 2028 · resets to 001

Endpoint 5
POST /api/invoices Create a new invoice 🔐 JWT
ℹ️ Content-Type: multipart/form-data — required to support optional e-invoice file upload. Items array must be JSON-stringified.
⚡ Do NOT send invoice_prefix or invoice_number — these are fully auto-generated by the backend using the current Indian Financial Year and an auto-incrementing sequence.

Endpoint 7
DELETE /api/invoices/:id Delete invoice permanently 🛡️ SUPER_ADMIN
⚠️ SUPER_ADMIN only. This action is irreversible. Invoice items are deleted via ON DELETE CASCADE. The associated e-invoice file is also removed from Cloudinary.

Path Parameters

ParameterTypeDescription
idnumberInvoice primary key
Response 200 OK
{ "message": "Invoice deleted successfully" }
Error Responses
StatusCondition
403User is not SUPER_ADMIN
404Invoice ID not found
500Delete query failed
